# Tier K's GNU Radio questions and the agent traces: text of the evaluation plan

For `Benchmark_Evaluation_Plan_to_7Dec.docx` (and its CAD 300 companion) and the two summaries, next to
`eval_plan_tier_f_text.md`. Qoherent's agent traces of 15–18 October are used in full for training.
They show GRC-Agent's catalog entries for almost every block (port types, parameter options, port
counts), and no trace ever ran a flowgraph (`reports/agent_traces.md`). The GNU Radio test questions
therefore ask what a block does, which only running it reveals. The published questions are a
reference set, and any seed draws a fresh set of the same composition, so the benchmark does not
depend on which blocks training uses: there is no test/train block split. The plans carry this text in
Table 1, §4.2, §6 and Table 7 (`_build_scripts/gen_eval_p1.py`, `gen_summary_p1.py`).

## §4.2 Tier K, paragraph "Items"

The 185 frozen test questions are stratified by origin, task type and difficulty. Only 38 of them are
specifically about GNU Radio, so we add 100 GNU Radio questions generated by a script. Each one states
a block, its settings and a short input, and asks for one number: the value of a given output item, or
how many items the block produces. The script runs the block in GNU Radio 3.10 and records its output,
so the answer is correct by construction. It keeps a question only when two runs agree and an
independent model of the block's documented behaviour gives the same number. A person checks the
wording of each question template. Tier K is closed-book: the model sees only the question, with no
tools. The 100 questions are the reference set. Any other seed gives a fresh set with the same blocks,
the same number of questions of each kind per block, and none of the reference set's instances. The
headline configurations also answer a fresh set from a private seed, fixed in advance by its hash; a
score clearly higher on the reference set than on the fresh set shows memorisation of the published
questions.

## §6 Contamination and data-flow controls, paragraph after "Further agent sessions"

**Agent traces.** Qoherent's 1,853 agent traces (15–18 October) are checked against the benchmark before
training:
- at the level of the task: the same goal or the same start graph as a Tier-F or Tier-A task counts as
  overlap, and none was found;
- by text: the traces are a corpus of the overlap audit;
- by the facts they expose: the traces show the block catalog but never run a flowgraph, so the GNU
  Radio questions ask about behaviour that only execution reveals.

Training data may cover any GNU Radio block, including what it outputs for a given input: the fresh
sets of §4.2 keep the score valid however a model was trained.
