# Composed flowgraphs (hand-written or programmatic chains): signature rule v2

GRC-Bench, 18 Oct 2026. Status: draft, pending team review. This replaces the chain-signature rule
of 14 Oct (v1, ordered block ids), which is withdrawn.

This note applies to every training-side flowgraph task, programmatic agent session or SFT/DPO
example whose graph is written by hand or composed by a script rather than derived from a seed
file. Seed files have their own rule: `flowgraph_seed_split.md` (never use a test or dev seed).

## The rule

For every graph you would emit (the solution graph of a build, modify, repair or tune item, and
every alternative solution you keep), compute its signature with GRC-Bench's code and emit the
graph only if **both** checks pass:

1. `compose.signature_split(compose.signature(graph)) == "train"`, and
2. `compose.signature_digest(compose.signature(graph))` is **not** listed in
   `flowgraph_reserved_signatures.txt` (this directory).

A graph that fails either check is a functional twin of a GRC-Bench test or dev task. Do not emit
it, and do not emit a near copy of it either.

```python
# from the GRC-Bench repository root: PYTHONPATH=src python ...   (pure Python + PyYAML, no GNU Radio)
import yaml
from grcbench.tier_f import compose

reserved = {l.strip() for l in open("handoff/training_team/flowgraph_reserved_signatures.txt")
            if l.strip() and not l.startswith("#")}

def allowed(grc_text: str) -> bool:
    sig = compose.signature(yaml.safe_load(grc_text))
    return compose.signature_split(sig) == "train" and compose.signature_digest(sig) not in reserved
```

## What the signature sees (and what it ignores)

The v2 signature is the sorted set of the *functional classes* of all enabled blocks (tone source,
noise source, filter, mixer, resampler, FM modulator, ...). The class map is documented in the
docstring of `src/grcbench/tier_f/compose.py`. By design it ignores:

* plumbing: Throttle, Head, Skip Head, Copy, every sink, probes, tag/message debug, type conversions,
  stream/vector reshaping;
* constant gains and offsets (Multiply Const, Add Const, a constant source feeding a multiplier or
  adder, a filter's gain), because a source's amplitude or offset does the same job;
* block order, and how many copies of a class there are (two tones or four, one filter stage or two);
* which of several equivalent blocks does a job (for example Rotator, multiplying by a complex
  oscillator and a Frequency Xlating filter are all a frequency shift; Noise Source and Fast Noise
  Source are both noise; a Low Pass Filter block and an FIR filter with low-pass taps are both a
  filter; a Constellation Modulator equals Chunks to Symbols plus a pulse-shaping resampler).

So inserting a Throttle, swapping two blocks, moving a gain or swapping in an equivalent block never
turns a non-train graph into a train graph. If a graph is not allowed, change what it *does*.

## Housekeeping

* The reserved list is regenerated by GRC-Bench (`./gb tier-f reserved`) whenever a test or dev task
  is added, re-themed or re-split. Its header names the signature version, the seed and the date of
  the class map; when the header changes, re-check every composed graph you generated before.
* The class map of 22 Oct 2026 gives a class to blocks that had none: Vector Insert counts as a mux;
  AND, OR, XOR, NOT and AND Const count as nonlinear; Complex to Mag/Phase counts as envelope and
  phase. Re-check every composed graph that uses one of these blocks (their ids are
  `compose.CLASS_MAP_ADDED`).
* Anything generated under the withdrawn v1 rule (seed `grc-bench-l1-signatures-v1-2026-10-14`) must
  be re-checked with v2.

  generates training data.
