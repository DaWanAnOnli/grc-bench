# Scoring code and statistics: second review

The rule cascade (`rules.py`), the judge template (`judge_prompt.py`) and the statistics package (`stats/`) had a second review on 18 Oct, two lenses each (correctness, methodology; the judge had one combined review). The full findings are in `round2_<part>_<lens>.json` in this folder.

**All 6 high-severity findings are resolved (6 of 6).** At sign-off (28 Oct, pre-registration §8, decisions 6 and 7) every medium and low finding is resolved, each with a test, except two: rules F7 stands as a pre-registered rule, and rules F5 is measured once the dev rubrics have graded numbers. Checks: `./gb test` (Tier-K rules, judge and statistics tests), `./gb score-k --selftest` (86 of 86, `tier-k-rules 0.6`) and `./gb stats selfcheck` (39 of 39).

## rules (`src/grcbench/tier_k/rules.py`)

| id | severity | status | finding |
|---|---|---|---|
| F1 | high | fixed in the 18 Oct pass; checked 22 Oct | In the numeric path, a correction written after the answer marker is ignored, and the rules decide the score instead of passing it to the judge. *Resolution:* a revision after the answer marker sends the answer to the judge (reason revised_after_answer); all 7 reviewer probes re-run. |
| F2 | high | fixed in the 18 Oct pass; checked 22 Oct | The symbolic path (exact and set) accepts hedged or revised answers at full credit. *Resolution:* a hedged parenthetical or a revision after a symbolic answer sends it to the judge (hedged_parenthetical, revised_after_answer); all 11 reviewer probes re-run. |
| R1 | high | fixed 22 Oct | The several-numbers rule ('a value followed by a conclusion word before the candidate is a step') scores an answer stated first on a derived value of the same dimension. *Resolution:* the first value after an explicit marker or in a box is the stated answer, so a later derived value with another credit sends the answer to the judge; without a marker the documented 'final stated answer' rule still applies (known limit, rules.py step 2); tests test_a_consequence_after_the_stated_answer_goes_to_the_judge. |
| R2 | high | fixed 22 Oct | _MARKER treats any prose 'answer is' as a final-answer marker equal to 'Final answer:', and the last marker wins. *Resolution:* a prose marker ('the answer is') counts only where no explicit marker exists; tests test_a_prose_marker_never_replaces_an_explicit_one. |
| F3 | medium | resolved 28 Oct (sign-off decision 6) | The colon is optional in the "final answer" pattern of _MARKER, so ordinary prose containing the phrase "final answer" counts as an answer marker. *Resolution:* "final answer" is a marker only before ":", "=" or "is", on its own line or in bold; pinned by `test_prose_final_answer_is_never_a_marker`. |
| F4 | medium | resolved 28 Oct (sign-off decision 6) | For several-part references, score()["credit"] (also the per-row credit in --batch output) is the mean over the parts even when a part has a unit or order-of-magnitude error. *Resolution:* the item's credit under P9 is `details["item_credit"]` and the `rule_only_credit` column of `--batch`; pinned by `test_part_zero_reaches_the_batch_rows`. |
| F5 | medium | open: measured once dev rubrics have graded numbers | The rule-only dev checks (proposal 5.1: "Development-set checks between training runs are scored by the rule cascade only, without the judge") will mostly measure answer style rather than accuracy. *Status:* the dev rubrics have `numeric` null and the dev split has no keys, so the end-to-end dev run of 28 Oct counts the answers without scoring them (`reports/e2e_dev.md`). |
| R3 | medium | resolved 28 Oct (sign-off decision 6) | In multi-part references whose parts share a dimension, when the label scoping fails (both labels in one sentence, written value-first), each part falls back to the whole-answer candidate rule. *Resolution:* two parts of one dimension decided on the same value, one of them without its label, go to the judge (`part_unassigned`). |
| R4 | medium | resolved 28 Oct (sign-off decision 6) | A unit word the parser does not know, written after a number with no '/' or 'per' after it (msec, usec, nsec, microsec, Kbit, Msamp, Mcps), is silently dropped. *Resolution:* msec, usec, μsec, nsec, microsec and Kbit are read; any other word after a bare number that is not in `UNIT_STOP_WORDS` sends the answer to the judge (`unknown_unit`). |
| R5 | medium | resolved 28 Oct (sign-off decision 6) | normalize() does not turn the LaTeX non-breaking space '~' into a space, so in '30~\text{kHz}' the unit is lost. *Resolution:* a "~" between a number and its unit is a space. |
| R6 | medium | resolved 28 Oct (sign-off decision 6) | For an exact block-id target, an answer that names the right block in words ('Throttle block') and puts only parameter names in code or snake_case gets a decided 0 (wrong_identifier). *Resolution:* other identifiers decide 0 only when every one is a block id of the frozen catalog (`reports/block_catalog.json`); a block named in words, with parameter or variable names, goes to the judge (`not_a_block_id`); pinned by `test_a_wrong_identifier_must_be_a_real_block_id` and `test_comparator_and_named_block`. |
| R7 | medium | resolved 28 Oct (sign-off decision 6) | The option-letter path reads a sentence-initial article 'A' as option A. *Resolution:* a bare capital is the first option letter only before the end of the clause, punctuation, a spaced dash, "&", "+" or "and"/"or" and another letter. |
| F6 | low | resolved 28 Oct (sign-off decision 6) | The rubric-writing guideline tells writers to give decibel tolerances in the `tolerance` field, but rules.py refuses that. *Resolution:* the guide gives decibel tolerances in `abs_tolerance`; pinned by `test_rubric_guide_db_template_parses`. |
| F7 | low | accepted as a rule 28 Oct (sign-off decision 6) | Credit for the same physical answer depends on which unit the rubric writer chose for the reference, which conflicts with the proposal's single "tiered relative-error credit" rule. *Rule:* decibel values are graded on the difference in dB (0.1 dB for full credit by default), stated in pre-registration §5.1. |
| F8 | low | resolved 28 Oct (sign-off decision 6) | Comparator and direction words are not handled. *Resolution:* a comparator sends the answer to the judge; a loss word next to a value sets its sign by rule (decision 7). |
| F9 | low | resolved 28 Oct (sign-off decision 6) | For an open-ended rubric (no numeric target), a truncated or empty answer is labelled method "symbolic". *Resolution:* method "rules". |
| R10 | low | resolved 28 Oct (sign-off decision 6) | Vpp, Vpk, Vp and Vrms all have scale 1 V, so a correct value in another voltage convention gets a decided 0 (outside_tolerance) instead of a conversion or the judge. *Resolution:* Vpp and Vpk convert exactly; Vrms converts only when the reference records `waveform: "sine"`, otherwise `voltage_convention` (0, a unit error). |
| R11 | low | resolved 28 Oct (sign-off decision 6) | For multi-part references, score() and the --batch output rows report the raw mean as 'credit', even when a part has a unit or order-of-magnitude error that policy P9 says zeroes the whole answer. *Resolution:* as F4. |
| R8 | low | resolved 28 Oct (sign-off decision 6) | An unevaluated expression given as the final answer is scored on its operand and decided (0 for a correct answer). *Resolution:* a term of ×, ·, "times", "twice", ..., or of "+", "plus", "minus", "over", with no relation (=, ≈, →, ...) after it in its sentence goes to the judge (`expression_answer`). A difference written with "-" ("35 kHz - 5 kHz") is read on its last term, a known limit: "-" also marks ranges, bullets and separators ("Answer - 30 kHz"). |
| R9 | low | resolved 28 Oct (sign-off decision 6) | Relative-dB families each have their own pseudo-dimension, so a plain 'dB' answer against a dBc, dBi or dBc/Hz reference gets a decided 0 (unit_mismatch), even when the text says 'relative to the carrier'. *Resolution:* a plain dB value is read in the reference's relative decibel unit (dBc, dBi, dBd, dBFS). |

## judge (`src/grcbench/tier_k/judge_prompt.py`)

| id | severity | status | finding |
|---|---|---|---|
| F1 | high | resolved 28 Oct (sign-off decision 7) | The judge route cannot settle the readings the rule cascade hands to it. *Resolution:* the rule cascade decides every number it reads two ways by fixed conventions (rules P4, P8) and a lower-credit tie-break (P11), so no answer needs the judge to choose a reading and none goes to a person. |
| F2 | medium | resolved 28 Oct (sign-off decision 6) | The tolerance tiers and the DU rule given to the judge for numbers stated in points are not the rule cascade's. *Resolution:* `_tier_text` is built from `CREDIT_TIERS`, `HALF_BAND_EXTRA`, `DB_TOLERANCE` and `MAGNITUDE_RATIO`, decibel bands included. |
| F3 | medium | resolved 28 Oct (sign-off decision 6) | The approved-rubric gate applies only to build_messages. *Resolution:* `check_reviewed` runs in `explain_score` and `score_from_verdict`. |
| F4 | medium | resolved 28 Oct (sign-off decision 6) | The hallucination check ("a judge's flag never zeroes a score unchecked") marks real names "absent" and so zeroes correct answers. *Resolution:* the index holds the programs GNU Radio installs; a name not found that has "::" or names gr-osmosdr is unchecked, not absent. |
| F5 | low | resolved 28 Oct (sign-off decision 6) | The pre-registration snapshot records nothing about how the judge is called: temperature, top_p, max_tokens, seed, JSON/structured-output mode, reasoning on or off. *Resolution:* `JUDGE_REQUEST` (temperature 0, fixed seed, ...) and `FAILURE_POLICY` are in the snapshot and the prompt hash. |
| F6 | low | resolved 28 Oct (sign-off decision 6) | parse_verdict breaks its contract ("Anything else raises VerdictError"): a deeply nested reply raises RecursionError. *Resolution:* a deeply nested reply is a `VerdictError`. |
| F7 | low | resolved 28 Oct (sign-off decision 6) | The documentation contradicts the template on what the judge sees. *Resolution:* the rubric guide says the scoring code applies the tolerance in `numeric`; `numeric_tolerance` is for the checkers. |
| F8 | low | resolved 28 Oct (sign-off decision 6) | The judge can see which model wrote an answer when the answer names itself. *Resolution:* listed model and vendor names (`REDACT_TERMS`) are masked as "[model]" before the judge reads the answer. |

## stats (`src/grcbench/stats/`)

| id | severity | status | finding |
|---|---|---|---|
| M1 | high | fixed in the 18 Oct pass; checked 22 Oct | The default for the pre-registered H1c test (the proposal's headline H1) mixes up the tier with the choice of test. *Resolution:* both tiers use the same test for H1c's significant-pairs count (PROPOSAL H1c-test, default Wilcoxon); test_size_matched_separation. |
| M2 | medium | fixed in the 18 Oct pass; checked 22 Oct | The proposed h1c_decision rule ('Tier F ahead in >= 95% of size-matched K subsamples') uses the share of without-replacement Tier-K subsamples as if it were a p-value. *Resolution:* h1c_decision decides on bootstrap intervals of F minus K; the subsample shares are descriptive only; test_h1a_and_h1c_decision_rules. |
| M3 | medium | fixed in the 18 Oct pass; checked 22 Oct | The H1c helpers (separation, size_matched_separation) refuse a panel whose configurations have different numbers of samples per item. *Resolution:* separation and size_matched_separation take model -> item -> samples with each model's own n; selfcheck 'H1c, mixed-n panel'. |
| M4 | medium | fixed in the 18 Oct pass; checked 22 Oct | agreement.judge_calibration()['passes'] and the judge part of h1a_decision apply only one kappa: the rubric-line gate. *Resolution:* judge_calibration computes both gates (rubric lines, answer score bands) and passes only when both pass; h1a_decision refuses a one-gate result; test_judge_calibration_gate_is_kappa_against_the_adjudicated_reference. |
| WS7-C1 | medium | fixed in the 18 Oct pass; checked 22 Oct | The H1c helpers (separation, size_matched_separation) cannot run on the panel the plan declares, because that panel mixes sample counts (n = 5, 3 and 1). *Resolution:* as M3. |
| WS7-C2 | medium | fixed in the 18 Oct pass; checked 22 Oct | judge_calibration()['passes'], and h1a_decision's judge part, test only one condition: the unweighted kappa on rubric lines. *Resolution:* as M4. |
| WS7-C3 | medium | resolved 28 Oct (sign-off decision 6) | In clustered mode, compare_paired's primary effect size uses an odds-ratio interval that assumes independent items: it is an item-level Clopper-Pearson interval on a_only/b_only. *Resolution:* with clusters, the odds-ratio interval is a cluster bootstrap (`clustered_odds_ratio`). |
| M5 | low | fixed in the 18 Oct pass; checked 22 Oct | compare_paired prints Table 8's MDE, which assumes independent items, even when its primary test is the cluster sign-flip test that the module proposes for confirmatory comparisons. *Resolution:* compare_paired prints a design-effect MDE next to a clustered test; selfcheck 'design-effect MDE'. |
| M6 | low | fixed in the 18 Oct pass; checked 22 Oct | The proposed H1a decision rule passes the bootstrap part when the MEDIAN Kendall tau between resample pairs is at least 0.8. *Resolution:* the H1a bootstrap rule is a named PROPOSAL (H1A_BOOT_RULE, H1A_BOOT_SHARE). |
| M7 | low | fixed in the 18 Oct pass; checked 22 Oct | The module adds about eight PROPOSAL decisions that change or extend the approved pre-registered definitions, and they are recorded only in code docstrings. *Resolution:* every analysis PROPOSAL is listed once in stats/proposals.py (`./gb stats proposals`); selfcheck 'PROPOSALS registry'. |
| WS7-C4 | low | resolved 28 Oct (sign-off decision 6) | With a single cluster, the bootstrap intervals collapse to zero width at the point estimate, and judge_passes accepts such an interval. *Resolution:* fewer than 2 clusters give no interval (NaN bounds) in the cluster bootstrap, the κ interval, the compression-cost difference and the clustered odds ratio; the odds ratio also gives none when its resamples have no spread. |
| WS7-C5 | low | resolved 28 Oct (sign-off decision 6) | Weighted Cohen's kappa on string labels without explicit categories silently orders the categories alphabetically, which gives a wrong weighted kappa for the rubric labels this project uses. *Resolution:* weights with text labels need `categories` (ValueError). |
| WS7-C6 | low | resolved 28 Oct (sign-off decision 6) | `./gb stats mde` ends in a raw Python traceback on out-of-range arguments instead of a clean argparse error. *Resolution:* argument errors are argparse errors. |
