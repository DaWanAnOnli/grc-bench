**The reference set: 100 test questions about 42 GNU Radio blocks**, at most 4 per block. Each asks for one number that comes from what the block does on a stated input: the k-th output item, or how many items it produces. The answer key is GNU Radio's own output: the generator runs the block (finite Vector Source(s) -> block -> File Sink(s)) in the sandbox and reads the recording. A question is kept only when two runs agree, an independent model of the block's documented behaviour gives the same number, and the rule cascade gives the key full credit and a wrong value less.

Why these questions: the agent traces used for training show the catalog entries of almost every block, but no trace ran a flowgraph (`reports/agent_traces.md`), so behaviour on a given input is held out. Any other seed gives a fresh set with the same composition and none of these instances (`./gb blockq --seed S --like-reference`; `reports/tier_k_fresh_sets.md`), so a model that memorised the published questions shows a gap between its two scores. Tier K is closed-book: the model under test sees only the question text.
