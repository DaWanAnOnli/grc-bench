## 2. Sources

- **20 composed tasks**, written from scratch on textbook themes. Their split is the split their signature-v2 cell hashes to.
- **10 tasks from GNU Radio 3.10.12 example flowgraphs** (GPL-3.0-or-later), converted to run headless and with their numbers changed (`perturbation` in each task). Each example is assigned to one split at file level (`splits/flowgraph_seed_split.json`), and a task uses only examples of its own split.
- **165 generated tasks** (`./gb tier-f generate`). A seeded generator draws a chain of stages on a set of tones, computes every expected feature exactly from the tones, and keeps a task only if its cell hashes to the task's split and the task passes every gate. Each task's `build.py` rebuilds it from its recorded attempt. An L2 task has a cell of its own. A single-rate chain of at most 5 blocks has few function combinations, and the retune template of L3 reaches few cells, so tasks of one split may share a cell: at most 8 L1 tasks and 2 L3 tasks per cell. Tasks of one cell share a `cluster_id`, and the clustered standard errors count the cell once: the test split has 116 cells, the dev split 38.

## 3. Split discipline

Signature v2 describes a flowgraph by the set of functions its blocks perform, so reordering blocks or adding an inert block (a Throttle) does not change it (`reports/tier_f_signature_v2.md`). A composed task's split must equal the split its reference cell hashes to. An example task's split comes from its example file, so its cell may hash to any split; that cell is reserved like every other test and dev cell. A generated task follows the composed rule.

- Tasks whose split disagrees with the rule: **0**.
- Groups of tasks that share a reference cell across splits: **0**.
- Reserved cells (reference and variant cells of test and dev tasks, plus the start and golden end-state cells of the Tier-A tasks, kept out of training data): **189** (128 hash to test, 40 to dev, 21 to train). The training team excludes all of them.

## 4. Gates

`./gb tier-f gates all` runs five gates on every task:
- **solvability**: the reference passes V1–V5 in 10 of 10 runs, 8 at a time;
- **size**: the reference fits in 3,000 tokens;
- **variants**: other valid solutions pass V5 (at least two);
- **start state**: a modify, repair or parameter-tune task's start graph fails;
- **mutation**: at least 90 % of the broken versions of the reference fail V5.
