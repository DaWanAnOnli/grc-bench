### Differences between the SFT rows and the pinned commit

| tool | field | path | SFT rows | pinned 6c98128 |
|---|---|---|---|---|
| run_command | parameters | `/properties/timeout_seconds/description` | Maximum seconds to wait (default: GRC_SHELL_TIMEOUT, 120s). | Maximum seconds to wait (default: GRC_SHELL_TIMEOUT, 600s). |
| run_flowgraph | parameters | `/properties/action/description` | 'start' to run the active flowgraph, or 'stop' to terminate it (SIGTERM, escalating to SIGKILL when shutdown stalls). | 'start' to run the active flowgraph, or 'stop' to terminate it (SIGTERM). |

Cause, evidence and decision (the pinned commit is authoritative for the benchmark):

- **run_command** `/properties/timeout_seconds/description`: collection setting (the shell timeout), not a schema change.
  - Evidence: The text is generated, not fixed: GrcShellToolset._apply_exec_approval (shell_tools.py L229-244 at 6c98128) writes f"{default_timeout():g}s" into it, and default_timeout() (L104-113) returns GRC_SHELL_TIMEOUT, else 600. 120 s is the value Qoherent used: GRC-Agent commit e437987 (28 Aug) records "GRC_SHELL_TIMEOUT set to 120s", and the collection harness sets it (experiments/dataset_collection/collect.py L483, `os.environ.setdefault("GRC_SHELL_TIMEOUT", "120")`). Every published revision from a6379e2 to 6c98128 reads the value from the .env file only (settings.get_env_value), and the recovered collect.py writes the campaign .env with GRC_PROVIDER and OLLAMA_CLOUD_MODEL only (L472-476). So the collection's .env or its GRC-Agent build (/opt/grc_agent in the SFT rows) differed from the published files in this one setting.
  - Decision: pinned default (600 s): the benchmark's .env sets no GRC_SHELL_TIMEOUT. Adding GRC_SHELL_TIMEOUT=120 to the run .env would reproduce the SFT text exactly and cap shell commands at 120 s; a team decision, recorded here.
- **run_flowgraph** `/properties/action/description`: unpublished GRC-Agent revision used for the collection.
  - Evidence: The text is run_flowgraph's docstring (agent.py L598 at 6c98128). `git log --all -S 'escalating to SIGKILL'` finds the phrase only in an audit note, docs/investigation/verify-c-new-tools.md (ba6658b, 25 Aug, an ancestor of 6c98128); no published commit up to 7d0de8c (18 Sep) has it under src/. At 6c98128 the stop path sends SIGTERM only (native_canvas.py L178, L406-440; exec_monitor.py has no SIGKILL), so the pinned text describes the pinned behaviour.
  - Decision: pinned text: it matches what the benchmark's stop actually does.

### On the wire

- Schema rewrite by pydantic-ai: the SFT stores pydantic-ai's tool definitions; before sending, pydantic-ai's JSON-schema transformer for OpenAI-style chat APIs rewrites 8 place(s) (change_graph): nested `$defs` get `additionalProperties: false` and lose their `title`, and free-form objects get `properties: {}`. OllamaModel (the teacher) applies the same transformer, so the teacher saw the same JSON.
- `strict`: GRC-Agent's OpenAIChatModel path marks 7 tools `"strict": true` (check_command, create_directory, duckduckgo_search, file_info, final_result, stop_command, web_fetch); pydantic-ai sets it when a schema is strict-compatible and the tool leaves `strict` unset (pydantic_ai/models/__init__.py L1816). The Ollama path never sends `strict` (its profile sets openai_supports_strict_tool_definition=False), so the teacher's requests had none (0). This is GRC-Agent's real behaviour against an OpenAI-compatible server and is kept; whether llama-server enforces it is recorded by the smoke test (it bears on the B0/B2 distinction).
- Message layout: roles ['system', 'system', 'user']: the fixed instructions and the active-flowgraph note travel as two system messages (the teacher's request: ['system', 'system', 'user']); `tool_choice` auto; per-tool keys description, name, parameters, strict.
- Output tool: besides the 22 function tools the model is offered `final_result`, GRC-Agent's structured final answer (output type `[GrcAgentResponse, str, DeferredToolRequests]`). The SFT `tools` field leaves it out by design (release README: "The `final_result` terminator tool isn't in the frozen tool schema").
